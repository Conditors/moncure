# Collector Service

Collector Service получает данные о товарах из поддерживаемых внешних сайтов и API и возвращает нормализованный результат в Monitoring Service.

В MVP Collector работает как фоновый worker и не владеет постоянными бизнес-данными.

## Ответственность

- получение задания из RabbitMQ;
- определение подходящего адаптера источника;
- безопасное выполнение внешнего HTTP-запроса;
- получение названия, цены, наличия и характеристик;
- нормализация результата;
- классификация ошибок;
- retry временных ошибок;
- ограничение частоты запросов к одному домену;
- публикация результата через RabbitMQ.

## Границы

Collector Service не должен:

- создавать товары;
- определять соответствие своего товара и конкурента;
- записывать данные в базу Monitoring;
- хранить историю цен;
- рассчитывать рекомендации;
- проверять права или тариф пользователя;
- определять, является ли изменение цены значимым.

## Адаптеры источников

Каждый поддерживаемый источник должен иметь отдельный адаптер с единым интерфейсом. Универсальный парсер произвольных сайтов не входит в MVP.

Адаптер отвечает за:

- проверку поддерживаемости URL;
- получение данных источника;
- разбор ответа;
- нормализацию результата;
- преобразование технической ошибки в известный тип ошибки Collector.

## Безопасность внешних запросов

Collector должен защищать систему от SSRF:

- разрешать только HTTP/HTTPS;
- блокировать localhost, private, link-local и metadata IP;
- повторно проверять адрес после DNS resolution и редиректа;
- ограничивать количество редиректов;
- применять connect, read и общий timeout;
- ограничивать максимальный размер ответа;
- валидировать тип содержимого.

## Надёжность

- повторная доставка одного задания не должна приводить к разным бизнес-результатам;
- retry применяется только к временным ошибкам;
- постоянные ошибки не должны бесконечно возвращаться в очередь;
- после исчерпания попыток сообщение направляется в DLQ;
- результат содержит идентификатор задания и correlation ID.

## Хранилище

Постоянная PostgreSQL-база Collector в MVP не нужна.

Redis может быть добавлен для распределённого rate limiting или кратковременной технической дедупликации. Redis не должен становиться источником бизнес-истины.

## Тестирование

- unit-тесты нормализации и выбора адаптера;
- тесты SSRF-защиты и редиректов;
- contract-тесты поддерживаемых источников;
- integration-тесты RabbitMQ, retry и DLQ;
- тестовый адаптер с детерминированным ответом для сквозных тестов.
