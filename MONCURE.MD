# Moncure

Moncure — платформа мониторинга цен конкурентов и формирования объяснимых рекомендаций по цене для небольших интернет-магазинов.

Предприниматель добавляет собственные товары, связывает их с предложениями конкурентов, отслеживает изменения цен и задаёт экономические параметры товара. Система помогает оценить рыночную ситуацию и предлагает цену, которая учитывает расходы и желаемую прибыль.

В MVP Moncure не изменяет цену в магазине автоматически. Окончательное решение принимает предприниматель.

## Цели проекта

- получить практический опыт командной разработки Python backend;
- изучить проектирование и эксплуатацию микросервисов;
- реализовать законченный продукт для портфолио;
- проверить возможность пилотного использования небольшими магазинами.

## Состав MVP

MVP включает пять бизнес-сценариев:

1. Добавление собственного товара по URL с предпросмотром и подтверждением.
2. Добавление и ручное подтверждение предложения конкурента.
3. Ручное и ежедневное обновление цен и характеристик.
4. Настройка расходов и расчёт рекомендуемой цены.
5. Просмотр истории цен и базовой аналитики.

В MVP не входят:

- реальные платежи и платные подписки;
- импорт всего каталога интернет-магазина;
- автоматическое изменение цен;
- поддержка произвольного сайта без адаптера;
- Kafka и отдельное аналитическое хранилище.

## Архитектура

Moncure состоит из четырёх бизнес-сервисов:

- **Account Service** — пользователи, организации, роли, аутентификация и доступ;
- **Monitoring Service** — товары, предложения конкурентов, импорт, синхронизация и история наблюдений;
- **Collector Service** — безопасное получение и нормализация данных из внешних источников;
- **Pricing Service** — расходы, стратегии и ценовые рекомендации.

Дополнительные компоненты MVP:

- Frontend;
- API Gateway;
- RabbitMQ;
- PostgreSQL;
- APScheduler;
- Notification Worker;
- Redis только при подтверждённой необходимости.

## Взаимодействия

Пользовательские запросы выполняются синхронно по HTTP:

```text
Frontend -> API Gateway -> Account / Monitoring / Pricing
```

Сбор внешних данных выполняется асинхронно:

```text
Monitoring -> RabbitMQ -> Collector
Collector -> RabbitMQ -> Monitoring
```

Фоновый пересчёт рекомендации:

```text
Monitoring -> RabbitMQ -> Pricing
Pricing -> RabbitMQ -> Monitoring
```

Collector не обращается напрямую к базе Monitoring. Сервисы обмениваются данными только через согласованные HTTP- и message-контракты.

## Владение данными

| Сервис | Данные |
|---|---|
| Account | пользователи, организации, роли и сессии |
| Monitoring | товары, предложения конкурентов, импорты, синхронизации и история цен |
| Pricing | расходы, настройки и рекомендации |
| Collector | не владеет постоянными бизнес-данными в MVP |

Каждый сервис, которому требуется постоянное хранение, владеет своей базой и миграциями. Прямое чтение или изменение таблиц другого сервиса запрещено.

## Технологический стек

- Python 3.13+;
- FastAPI и Pydantic v2;
- SQLAlchemy 2.x Async и PostgreSQL;
- Alembic;
- RabbitMQ;
- HTTPX;
- APScheduler;
- Redis при необходимости;
- Pytest и Ruff;
- uv;
- Docker и Docker Compose.

```text
moncure/

├── pricing-service/
├── docker-compose.yml

```

Это монорепозиторий: все сервисы находятся в одном Git-репозитории, но остаются независимо собираемыми и развёртываемыми приложениями.

## Инженерные правила

- бизнес-логика не размещается в FastAPI routers;
- сервис не импортирует код другого сервиса;
- интеграционные контракты версионируются;
- обработчики сообщений должны быть идемпотентными;
- ошибки одного внешнего источника не останавливают общую синхронизацию;
- пользователь не должен получать доступ к данным другой организации;
- новые сервисы и технологии добавляются только при подтверждённой необходимости;
- значимые архитектурные решения обсуждаются командой до реализации.
